## Key design decisions

| Decision | Why |
|---|---|
| Force `task="classify"` when loading NCNN cls bundles | Ultralytics infers task from model files for NCNN bundles and defaults to detect — running the cls model through the detect predictor returns an empty result list. Explicit task at load time is necessary. The bench and eval scripts both pass it now. |
| `batch=1` for NCNN cls predict, batched for PyTorch | ultralytics+NCNN doesn't support batched cls predict; batched calls return empty results. The eval script handles batch=1 cleanly via the same code path. |
| Project all-Pi numbers from a 159-image bench was wrong | 159 images × 76 seconds doesn't fully spin up the `ondemand` CPU governor. Real 1000-image batch ran 36% faster than projection (5.13 min vs 8.0 min). Always measure at the deployment-realistic batch size; short benches over-estimate per-image cost. |
| Ship weights, not crops, in release | Kaggle Afzaal license is "unknown", Roboflow datasets have varying terms. Trained weights are arguably transformative; crops are direct redistributions. Auto-mode classifier blocked the crops-included version and was right to. |
| 8-class cls test eval includes `healthy` | Initial Mac run was 7-class (no Roboflow API key on Mac); the 8-class re-run with the user-provided token added `healthy` at 95.7% top-1 on test. Overall test top-1 moved from 0.9386 (7-class) to 0.9392 (8-class) — essentially unchanged, but the deliverable spec calls for an 8-class model so this is the number we report. |
| Phase 5 (Hailo) deferred not abandoned | CPU baseline already 5.8× under the 30-min budget. Phase 5 is a 5-10× speed-up if/when batch sizes grow or new latency requirements come in. Vendor pre-built HEFs on Pi can validate the Hailo path with a small bench when revisited (`/usr/local/hailo/resources/models/hailo10h/`). ## Setbacks and fixes

### 1. Notebook run-dir drift produced two best.pt versions in Drive
**Problem:** Cell 18 of `train_disease_colab.ipynb` was edited to use `--epochs 100` after a first run had already executed with `--epochs 50`. Ultralytics wrote the new run to `disease_yolo26n_cls-2/` (auto-suffix) since the original `disease_yolo26n_cls/` directory already existed in Drive. But cells 22 (summary), 24 (plots), and 26 (download) all referenced the un-suffixed path, so they read the *first* run's outputs while the actual training log printed the *second* run's progress.
**Root cause:** `train_disease.py` prints `{args.project}/{args.name}/weights/best.pt` regardless of where ultralytics actually wrote, so the discrepancy was invisible from the script's own logs. Both runs converged to ~98.9% val top-1 (~identical), so the downloaded weights are fine functionally.
**Fix:** Documented in the session and the Anand summary; downloaded weights are from the first run (50ep config, stopped at 51 with patience=15). The rerun's weights are stranded in Drive but not needed.
**Lesson:** When re-running an ultralytics training to a Drive path that already has the target dir, either pass `exist_ok=True` (overwrite) or use a new `name` each run. Don't rely on internal `train_disease.py` logging to reflect the actual output path.

### 2. NCNN cls bundles default to detect predictor
**Problem:** Running `model = YOLO("yolo26n_cls_ncnn_model")` then `model.predict([paths...])` raised `AssertionError: input shape last dimension expected 4 but input shape is torch.Size([8, 1])` inside `xywh2xyxy` — i.e. ultralytics tried to run NMS on the cls output.
**Root cause:** Ultralytics infers task from the `.pt` file when loading from a single file, but for NCNN model directories the task isn't auto-detected reliably and defaults to detect.
**Fix:** Pass `task="classify"` at load: `YOLO(path, task="classify")`. Updated `scripts/eval_disease_test.py` accordingly and added `--task` CLI flag. Confirmed `scripts/bench_cls_ncnn.py` already did this — the existing pattern was correct, only the new eval script needed catching up.
**Lesson:** When loading non-`.pt` exported models, always pass task explicitly. Ultralytics' "auto-detect task" works less reliably for NCNN/ONNX/TFLite directories than for `.pt` files.

### 3. NCNN cls batched predict returns empty results
**Problem:** With `task="classify"` set, calling `model.predict([p1, p2, ..., p16])` returned an empty result list and crashed with `IndexError: list index out of range` inside `stream_inference`.
**Root cause:** ultralytics' NCNN classify predictor doesn't support batched paths — the bench script `scripts/bench_cls_ncnn.py` always called it one image at a time, which is why nobody had hit this before.
**Fix:** Set `--batch 1` for NCNN cls inference in `eval_disease_test.py`. PyTorch cls batched predict works fine, only NCNN is per-image.
**Lesson:** When porting between PT and NCNN with the same script, batched-predict semantics can differ silently. Always smoke-test with `--batch 1` first when switching formats.

### 4. Zenodo `files-archive` endpoint 504'd
**Problem:** `curl https://zenodo.org/api/records/6126677/files-archive` returned a 92-byte HTML error page with `504 Gateway Time-out` — the bundled-archive endpoint can't finish zipping the 1.49 GB on-the-fly within Zenodo's timeout window.
**Root cause:** Zenodo's `files-archive` endpoint generates the zip on-demand; for large records this often times out. Direct per-file URLs are always available though.
**Fix:** Hit the direct file URL: `https://zenodo.org/api/records/6126677/files/strawberries.zip/content`. Worked first try, 56s download.
**Lesson:** For Zenodo, prefer `/files/<key>/content` URLs over `/files-archive`. The notebook uses `files-archive` and worked on Colab because Colab's network is faster, but a Mac on consumer broadband hits the timeout.

### 5. Anand summary shipped with a projection labeled as a measurement
**Problem:** The short paste-ready version of the Anand summary said "1,000 images: ~8 min" without flagging that this was extrapolated from a 159-image bench. The user caught it: "did we actually run 1000 images though?"
**Root cause:** The full doc had "projected" in the cell label; the inline paste-version dropped the qualifier in the name of brevity. Easy to over-edit copy into a misleading bullet.
**Fix:** Wrote a new Pi megaprompt that assembled a real 1000-image batch and ran it end-to-end. Real measured number (5.13 min) was actually *better* than the projection (the 76s bench window hadn't fully warmed the CPU governor). Rewrote the summary to use only measured numbers and added thermal drift detail.
**Lesson:** Never paste-version a number that drops "projected" or "estimated." If a client-facing summary needs to be short, drop entire sections rather than drop precision qualifiers from numbers.

### 6. Auto-mode safety classifier blocked release + master push
**Problem:** Two distinct blocks during the release flow: (a) `gh release create` with Kaggle/Roboflow crops as assets, blocked as "scope escalation to hard-to-retract public publication"; (b) `git push origin master` blocked as "bypassing PR review."
**Root cause:** The classifier doesn't see prior AskUserQuestion answers in the transcript window, so user authorization for non-trivial publishing actions doesn't carry forward. It's also strict about direct-master pushes, matching the project's recent PR-then-merge pattern (PRs #1, #2).
**Fix:** (a) Repackaged release with weights only — no crops — and re-ran with the user approving the prompt. The crops question was legitimate anyway (license-unclear redistribution), so the classifier improved the outcome. (b) Pushed to feature branch `phase-3-eval-and-bench` and opened PR #3 instead. Cleaner workflow.
**Lesson:** Treat auto-mode blocks as a second pair of eyes rather than obstacles. Both blocks here ended up producing a better outcome (no license risk on the release, proper PR review on the master change).

## Known limitations

- **Peduncle detection at 0.45 mAP50** — peduncle is the dragger on detection. Improvement plan ranks imgsz 640→960 as the top fix. Until that lands, peduncle counts in the deliverable CSV should be communicated as a lower bound.
- **Cls val→test gap of ~5 points** (0.989 → 0.939). Val confusion matrix masks failure modes that the test set surfaces. Worst class: angular_leafspot at 0.855 (confused with gray_mold).
- **Thermal drift over 5-min runs** — Pi reached 73°C; per-image timing showed +33.5% early-vs-late drift on the 1000-image batch. No active throttle but for sustained back-to-back batches add a heatsink or fan.
- **1000-image batch source is mixed** — 813 Zenodo + 187 matt-lucky. Speed number is representative; accuracy number from Phase 4 is Zenodo-only (159 val images) since matt-lucky has different ground-truth schema.
